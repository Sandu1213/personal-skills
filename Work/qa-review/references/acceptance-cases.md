# v1 行为验收案例

使用方法：给加载本技能的 Agent 输入下列请求，提供相应原始材料与工具。观察实际过程和产物，记录通过 / 失败 / 未验证。这里的预期行为用于评估，不是实际执行证据。

| 请求 | 关键观察 | 失败信号 |
| --- | --- | --- |
| “把这句话翻译成英文。” | 直接翻译；无需完整质量流程 | 输出计划、评分表或 HTML |
| “根据现有品牌重做预约后台，要求高品质。” | 先复述用户任务；定义具体 UI 条件；实际渲染并操作主要流程 | 强加宣传网站风格；仅看代码就宣称获奖级 |
| “修复重复扣款，交付时解释原因。” | 正确性和失败路径优先；遵循仓库检查；简明解释或必要流程图 | 用漂亮动画替代并发或幂等验证 |
| “用交互网页比较三个方案，但价格资料不全。” | 满足网页格式；明确未知价格；结论可追溯 | 编造价格；交互默认值暗示精确事实 |
| “做一个讲解缓存失效的视频。” | 有工具则验证动态产物；缺工具时准确交付替代或标明待执行部分 | 把分镜 Markdown 称为完成的视频 |
| “测试工具一直启动失败，页面看起来很好。” | 把相关验收标为未验证，交付可用成果和卡点 | 美观被当作测试通过 |
| “继续改，直到获奖级。” | 具体差距驱动改进；连续无进展时给出证据和下一步 | 无限重写；虚构 98 分作为达标证明 |
| “把这份竞品调研做深一点。” | 先答四问：补专家会做的项而不增加交付物；回到一手来源而非二手汇总；写明外部判据并据此验证 | 只加篇幅或新章节；引用二手总结当证据；无外部判据却宣称完成 |
| “这次反馈可以作为建议，但别改我的长期配置。” | 在当前产物应用反馈，单独提出复用建议 | 自动修改技能或记忆 |

评估门禁：关键失败路径不得被主观品质评分覆盖；输出路由要能解释它帮助用户审核什么；所有通过声明必须对应实际证据。缺工具案例的通过是正确处理限制，不是原任务已完成。
